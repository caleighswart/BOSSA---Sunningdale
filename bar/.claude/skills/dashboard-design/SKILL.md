# BOSSA Bar Dashboard — Design System (v3 "Control Board")

The dashboard at `https://bossa-sunningdale.netlify.app/` is generated by [bar/generate_dashboard.py](../../../generate_dashboard.py). The current live design is **v3, the "Control Board"** — a clean, data-dense operations console: a fixed dark sidebar, a topbar, a 5-tile KPI strip, and chip-filtered tables. It reads as a professional internal tool, not a marketing surface.

**This supersedes the earlier warm-cream "BOSSA brand" direction (v1/v2).** The user explicitly approved a slate + blue control-board redesign on 2026-06-11 and chose to override the cream/yellow/Inter brand. Do **not** reintroduce cream backgrounds, a yellow accent, a dark hero band, or Plus Jakarta Sans. See memories `bar-dashboard-design-locked-v3-2026-06-11` and `[[dashboard-typography-preference]]`.

The whole stylesheet lives in the module-level `_STYLE_BLOCK` constant in `generate_dashboard.py` (a plain string interpolated into `build_html` as `{_STYLE_BLOCK}`). Treat the values below as a mirror of that constant — if you change one, change both.

## Design tokens

**Palette** — derive every colour from the `:root` custom properties. One blue accent only; do not add a second accent hue.

| Token | Hex | Use |
|---|---|---|
| `--bg` | `#F2F4F7` | Page background (cool off-white) |
| `--bg-soft` | `#F8FAFC` | Table headers, hover rows, soft fills |
| `--panel` | `#FFFFFF` | Card / table surfaces |
| `--line` | `#E2E7EF` | Card + table borders |
| `--line-strong` | `#D8DEE7` | Inputs, chips, stronger dividers |
| `--ink` | `#0F172A` | Primary text, numbers, active chip fill |
| `--ink-soft` | `#334155` | Secondary text |
| `--ink-mute` | `#64748B` | Labels, captions, column heads |
| `--ink-faint` | `#94A3B8` | Placeholder / footer text |
| `--side` | `#0E1726` | Sidebar background (dark slate) |
| `--side-hi` | `#1E2C44` | Active sidebar item |
| `--action` / `--accent` | `#1D5BD8` | **The single accent** — CTAs, links, active coverage seg, order-qty, focus ring |
| `--action-hover` | `#1747AC` | Accent hover |
| `--accent-bg` | `#EFF4FE` | Accent tint (order-qty chip bg) |
| `--crit` | `#DC2626` | Critical stock (bg `#FEF1F1`, line `#F6CBCB`) |
| `--low` | `#C2620A` | Low stock text (bg `#FDF3E4`, line `#F2D9AE`); **fill bar uses `#D97706`** |
| `--ok` | `#15803D` | Healthy text (bg `#EBF7EE`, line `#BFE3C8`); **fill bar uses `#16A34A`** |
| `--info` | `#7C5CBF` | Variances (bg `#F1ECF9`, line `#DCD0EE`) |

Status colours are semantic only (red = critical stock, amber = low, green = healthy, plum = variance) — never decorative.

**Typography** — one family, used everywhere. The dashboard is a business tool: readability first.

- **All UI text:** `"IBM Plex Sans", -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` (weights 400 body, 500 secondary, 600 headings/labels, 700 for the brand mark, KPI strip values use mono).
- **Numbers (SOH, par, fill %, KPI figures):** `"IBM Plex Mono", ui-monospace, "SF Mono", monospace` (400/500/600), with `font-variant-numeric: tabular-nums;` so columns align.
- **Do NOT use** Plus Jakarta Sans, Inter, Bebas Neue, Oswald, Anton, Playfair, or any condensed/slab/display font. Brand identity comes from the **palette + layout**, not typography.
- Reserve uppercase for tiny labels (≤11px) — KPI captions, table column heads, cat-section names — with letter-spacing ≤ 0.08em. No wide-tracked all-caps headings.

Load both via one Google Fonts `<link>` in the head: `IBM+Plex+Sans:wght@400;500;600;700` + `IBM+Plex+Mono:wght@400;500;600`.

**Shape & spacing**
- Border radius: `--radius-l 12px` (cards), `--radius-m 10px`, `--radius-s 6px` (chips/inputs 6–8px). Pills/sidebar counts use `999px`; data containers never do.
- Borders: 1px `--line` on cards/rows. Sidebar width `--sidebar-w: 228px`; page gutter `28px`.
- Shadows: minimal — a 1–2px card lift (`0 2px 8px rgba(15,23,42,0.06)`) and the sticky batch bar. No glows or layered drop shadows; no gradients.

## Layout principles

1. **Fixed dark sidebar, not a header bar.** `.sidebar` (`--side`) pinned left, `body { padding-left: var(--sidebar-w); }`. Contains the `BOSSA` wordmark + "Sunningdale · Bar stock", three `.prim` nav buttons (Stock / Orders / Admin) each with a `.side-count` badge (the Orders count uses `side-count-hot` = red), and a `.side-foot` "PilotLive sync" stamp pinned to the bottom. Collapses to a sticky top bar under 640px.
2. **Topbar.** `.topbar` with an h1 ("Bar stock") + a weekday-qualified date sub ("Thursday, 11 June 2026 · live from PilotLive") and a blue `.cta-primary` ("Send supplier orders · N") that jumps to Orders.
3. **5-tile KPI strip.** `.kpis` grid of `.kpi` tiles — Critical / Low / Healthy / Products tracked / Stock value — mono numerals, small uppercase caption, a coloured top-border per tone (`data-tone="crit|low|ok"`). The first four are buttons that jump to the matching tab; Stock value is `.kpi-static`.
4. **Chip-filter secondary nav.** `.secondary-nav` shows one `.chip-group` per section; chips are pill-shaped, 1px border, active chip = `--ink` fill / white text, with a coloured count badge (`c-crit`, `c-low`, `c-ok`, …).
5. **Tables breathe.** `.stock-table` on `--panel`, `--bg-soft` headers, 9–14px row padding, hover = `--bg-soft`, a 3px semantic left-edge on `row-critical/low/healthy/variance`. Grouped into collapsible `cat-section` `<details>` blocks.

## Components

- **Status pills** (`pill-critical/low/healthy/variance`): tinted background + semantic text, `999px` radius, 11px, light tracking. Not uppercase.
- **Fill bars** (% of par): `.pb-wrap` track (`--line-soft`, 5px tall, 3px radius) + `.pb-fill-crit/low/ok`. The `_pct_bar` helper in `generate_dashboard.py` builds these — keep its structure.
- **Order cards** (Orders tab): white `.supplier-card`, supplier name + meta, per-category sections, blue primary `.order-btn` (`::after` arrow), order-qty shown as a blue `--accent-bg` chip.
- **KPI tiles, search bar, coverage segmented control, batch/history panes** — all already styled in `_STYLE_BLOCK`; reuse their classes.
- **Empty states**: centred `.empty` panel, muted text ("Nothing to flag — looking good."). No icon-only "all clear".

## Voice (microcopy)
Plain and operational. Empty states like "Nothing to flag — looking good."; sentence-case section titles ("Order history", not "ORDER MANAGEMENT"); human dates ("Thursday, 11 June 2026"). Zero emoji in the HTML.

## Don'ts

- ❌ No second accent colour — `#1D5BD8` blue is the only accent. (Status red/amber/green/plum are semantic, not accents.)
- ❌ No cream/yellow palette, no dark "hero band", no giant display-font hero number — those were v2 and are retired.
- ❌ No Plus Jakarta Sans, Inter, or any condensed/display/slab font (Bebas Neue, Oswald, Anton, Playfair). IBM Plex only.
- ❌ No emoji, no gradients, no icon libraries (Font Awesome, Heroicons).
- ❌ No `border-radius: 0` (too cold) and no pill/`999px` shapes on anything wider than a small badge.
- ❌ No wide-tracked all-caps headings (> 0.08em).
- ❌ Don't rename the data-side contract: the row helpers (`_stock_table`, `_grouped_stock_table`, `_orders_tab`, `_stock_order_tab`, `_pct_bar`, etc.) and class names (`row-*`, `cat-section`, `supplier-card`, `batch-*`, `history-*`, `email-settings`, `pb-fill-*`, `sidebar`, `prim`, `kpi`, `topbar`) are referenced by the embedded JS — change styling, not structure.

## When applying this

1. The **entire CSS** lives in the module-level `_STYLE_BLOCK` constant in `generate_dashboard.py` (a plain, non-f-string `r"""<style>…</style>"""`, so its braces are literal). Edit colours/layout there.
2. The **body shell** (`.sidebar` + `.topbar` + `.kpis`) and the count/value interpolations live inline in `build_html`'s return f-string. The `<script>` block (tab/section switching, search, coverage, batch, history) is unchanged from v2 — leave it alone unless behaviour changes.
3. Keep all data structures and Python logic identical — visual work is a CSS/HTML-shape change only.
4. Add/keep the IBM Plex Google Fonts `<link>` in `<head>`.
5. Test by running `python build_design_template.py` from `bar/` (a fixture dataset, no PilotLive creds needed) → open `/tmp/bossa_dashboard_design_template.html` locally before committing. `generate_dashboard.py` itself needs live SSRS creds, so iterate on the template harness.
